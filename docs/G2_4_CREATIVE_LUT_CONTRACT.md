# G2.4 Creative Filter GPU Preview Contract

## Status

G2.4a (`grayscale`, `invert`) has native Metal realtime preview and exact numeric parity against the Rust/photon-rs semantics.

G2.4b moves the remaining Photon preset filters to a Rust-generated canonical LUT workflow instead of reimplementing Photon internals in Metal.

## Scope

Creative preset filters:

- `vintage`
- `oceanic`
- `lofi`
- `dramatic`
- `golden`
- `pastel_pink`

## Source of truth

Rust remains authoritative. The canonical creative LUT generator must call the same `photon_filters::apply` path used by committed edits/export at intensity `1.0`.

Metal must not contain independently maintained preset coefficients or HSL conversion code for these filters.

## Canonical LUT

- Grid: 33 × 33 × 33
- Input domain: RGB `[0, 1]`
- Storage source: RGBA8 generated by Rust
- Alpha: 255
- Sampling: same texel-center 3D LUT rule already verified by the G1 Film parity harness
- Runtime intensity: blend original color with LUT result using the same normalized `0.0 ... 1.0` intensity contract as `rust/src/photon_filters.rs`

Conceptually:

```text
source RGB
  -> canonical creative 33³ LUT (Rust-generated)
  -> effected RGB
  -> mix(source, effected, intensity)
  -> preview output
```

## Asset layout

Creative LUT assets must be namespaced separately from Film LUTs to avoid treating a creative preset as a Film Profile.

Recommended bundle layout:

```text
gpu_luts/
  film/
    <film-profile>.rgba8
  creative/
    vintage.rgba8
    oceanic.rgba8
    lofi.rgba8
    dramatic.rgba8
    golden.rgba8
    pastel_pink.rgba8
```

If the existing build pipeline cannot be migrated without breaking G1 compatibility, keep the current Film asset paths intact and add only a `gpu_luts/creative/` namespace.

## Runtime rules

1. Dart sends only creative filter id + intensity.
2. Image pixels remain native.
3. Metal loads/caches a creative 3D LUT when the selected preset changes.
4. Intensity-only slider updates must not recreate/reload the LUT texture.
5. Selecting another tool clears the active creative GPU draft.
6. Unsupported/missing creative LUT asset -> immediate Rust preview fallback.
7. Apply/Cancel/Undo/Redo/export remain Rust-authoritative.

## Verification gate

Before enabling a preset as GPU-supported by default:

- Rust-generated reference LUT exists.
- Metal 33³ sampler passes the existing LUT numeric parity rule.
- Creative intensity blend parity is <= `1/255` max channel error.
- 1024² command-completion p95 remains <= 16.67 ms on the G2 reference device.
- Visual handoff from Metal live draft to Rust committed preview has no obvious jump beyond expected LUT interpolation tolerance.

## Why LUT generation is preferred

Some Photon presets are simple per-channel operations while others chain contrast, grayscale, channel offsets, color mixing, or HSL operations. Encoding those internals independently in Metal creates a second source of truth and increases drift risk when the Rust dependency changes. Rust-generated LUTs preserve a single authoritative implementation while reusing the already-verified G1 Metal LUT sampler.
