# PixelCraft Code Walkthrough

เอกสารนี้อธิบาย architecture ปัจจุบันของ PixelCraft ตั้งแต่เปิดแอป เลือกรูป ส่งงานผ่าน `flutter_rust_bridge` ไปยัง Rust, operation history, full-resolution export, transform tools, responsive editor และ workflow ของ Adjust/Creative Filters

> หลักการสำคัญคือ Flutter รับผิดชอบ UI และ state projection ส่วนงาน decode, filter, histogram, transform, operation replay และ export อยู่ใน Rust โดยงานหนักที่เรียกผ่าน synchronous FRB API ถูก dispatch ผ่าน background Dart isolate เพื่อลดการ block UI isolate

## Current flow summary

```text
Select image
  -> Rust load_image
  -> preview/original preview/histogram
  -> background prewarm of creative-filter thumbnails

Adjust slider
  -> drag: Flutter only
  -> release: background isolate -> Rust commit one Filter operation

Creative Filters
  -> thumbnails already cached from original preview
  -> first tap: commit one creative-filter operation at 1.0
  -> show intensity slider
  -> another filter/intensity: undo active creative filter + commit replacement
  -> operation count stays stable

Transforms / Undo / Redo / Export
  -> background isolate -> synchronous FRB -> Rust operation engine
```

## Operation-based engine

`rust/src/engine.rs` keeps original compressed bytes, a list of `EditOperation`, an active `cursor`, preview size settings, and temporary filter-transaction state. Preview and full-resolution export are generated by replaying active operations from the original image rather than by chaining stored PNG snapshots.

Supported operations include Filter, Crop, Rotate90, RotateDegrees/Straighten, FlipHorizontal, FlipVertical, and Resize. Undo decreases the cursor. Redo increases it. A new commit after Undo truncates the redo tail before appending the new operation.

## Flutter state and background processing

`lib/state/editor_controller.dart` projects the Rust engine state into Flutter. It tracks preview bytes, original preview, histogram, Adjust filter selection, creative filter selection/intensity, thumbnail cache, current tool, busy state, and session cursor values.

`lib/core/image_engine.dart` wraps synchronous FRB calls and provides background helpers based on `Isolate.run()`. Heavy committed operations therefore execute away from the UI isolate while Flutter remains responsible for local slider movement and rendering.

## Adjust controls

`FilterSlider` changes only its local thumb/value while the user drags. Rust is called once on `onChangeEnd`. This avoids processing brightness/contrast/saturation/blur/sharpen for every pointer event.

```text
Drag slider -> local Flutter state
Release -> commitFilterValue(finalValue)
        -> background isolate
        -> Rust begin_filter / update_filter_preview / commit_filter
        -> one history operation
```

## Creative filter previews

Creative filters currently include grayscale, invert, vintage, oceanic, lofi, dramatic, golden, and pastel pink. There is no default selected creative filter.

Thumbnail generation starts automatically after the image finishes loading. The source is `originalPreviewBytes`; opening the Filters tool normally reuses the cached results and does not trigger regeneration after each filter tap.

`rust/src/api.rs::generate_filter_previews()` is optimized for browsing thumbnails:

1. decode the source once,
2. resize it once to about 180 px max edge,
3. apply all creative filters from the same small base,
4. run variants in parallel with Rayon,
5. encode each result as PNG.

The thumbnails are intentionally stable style references. They do not mutate after a user tries Vintage/Oceanic/etc., so browsing another filter never uses the previously filtered thumbnail as its source.

## Creative filter replacement and intensity

The first creative-filter tap commits one Filter operation at intensity `1.0` and shows a `0.0..1.0` intensity slider.

If the user then selects a different creative filter, or changes the intensity and releases the slider, PixelCraft replaces the active creative-filter operation instead of stacking another filter on top. Internally the background task performs an Undo of the active creative-filter operation and commits the new filter/value from the same pre-filter image state.

For example, if the current base is already Adjusted + Cropped:

```text
Adjusted + Cropped -> Vintage
```

switching to Oceanic becomes:

```text
Adjusted + Cropped -> Oceanic
```

not:

```text
Adjusted + Cropped -> Vintage -> Oceanic
```

The operation count therefore remains unchanged while the user browses filters or tunes intensity.

## Transform tools

Crop uses normalized centered presets (1:1, 4:3, 3:4, 16:9, 9:16). Rotate supports quarter turns. Flip supports horizontal and vertical. Straighten uses -15°..15° and, like other sliders, processes only after release.

## Before / After

`original_preview()` produces a bounded preview from the original source. Long press in the editor temporarily switches `visiblePreview` to that original image.

## Full-resolution export

Export replays active operations from the original resolution and supports PNG, JPEG quality, and WebP. `ExportFileService` saves to app documents and can invoke the system share sheet. Direct Android Gallery / iOS Photos insertion is not implemented yet.

## Responsive UI

`EditorScreen` uses a compact vertical layout on phones and a side tool panel from 900 px upward. `EditorToolPanel` exposes Adjust, Filters, Crop, Rotate, and Details. Controls are temporarily disabled while a committed background operation is running.

## FRB code generation

The new batch thumbnail API changes the Rust public API. Regenerate bridge files before validation:

```bash
make codegen
```

Commit the generated FRB files with the branch.

## Testing

Controller/widget tests cover commit-on-release Adjust behavior, thumbnail prewarming, no default creative filter, cached thumbnails, creative-filter replacement, intensity replacement, transforms, undo/redo, and export. Golden baselines should be regenerated and reviewed whenever the Filters layout changes.
