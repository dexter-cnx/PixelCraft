# PF3 Capture -> Process -> Save

PF3 keeps Camera capture explicit and deterministic:

- capture a clean camera JPEG;
- render the committed `CameraLook` in Rust;
- save only the rendered JPEG to the system Gallery;
- remain in Camera after success/failure feedback;
- Gallery/external imports continue through the normal Editor path.

## Film / Filter preview thumbnails

Film/Filter tray previews must never trigger a real still capture.

Current implementation:

- `_enableStillCaptureLookPreviews = false`, so opening Film/Filter does not call `capturePhoto()`;
- iOS requests an on-demand snapshot from the active Metal camera preview through `dev.pixelcraft/gpu_preview_snapshot_v1`;
- Android requests an on-demand snapshot from the active OpenGL-backed `TextureView` through the same `dev.pixelcraft/gpu_preview_snapshot_v1` channel;
- while the Film/Filter tray is mounted, Dart refreshes the bounded live thumbnail source at roughly 300 ms intervals and cancels immediately when the tray is disposed;
- each request is bounded to a small JPEG thumbnail and coalesced on the Dart side; live frames are not streamed continuously over MethodChannel/FRB;
- generated preview bytes, when available, take priority over the live snapshot source;
- if the live snapshot is unavailable, Film/Filter tiles reuse `CameraRecentThumbnail`, the same most-recent accessible photo shown by the Camera Gallery control;
- Film fallback tiles apply the existing camera Film approximation matrices;
- Grayscale and Invert use deterministic color matrices;
- creative LUT filters that do not yet have generated bytes use the neutral source rather than pretending to be a canonical LUT result.

The previous shutter-backed thumbnail experiment remains disabled. Neither live snapshot path touches the still-capture transaction (`AVCapturePhotoOutput` on iOS or the Android clean-capture path), and opening Film/Filter must not produce shutter sound or interrupt Camera capture state.

## Physical validation

Validated:

- Android Film/Filter live snapshot follows the current camera scene with no still-capture side effect or camera interruption;
- iPhone Film/Filter live snapshot follows the current camera scene with no shutter sound or camera interruption.

Before PF3 is marked complete, still validate:

- Android neutral and combined Film + Filter + Adjust capture/save;
- iPhone neutral and combined Film + Filter + Adjust capture/save;
- portrait and landscape shutter orientation both save with the correct final visual orientation on Android and iPhone;
- saved JPEG visually corresponds to the committed final CameraLook;
- capture processing/saving feedback remains on Camera via SnackBars;
- failure/Retry preserves the clean temporary source where practical;
- Gallery still opens the normal Editor path;
- Camera remains responsive/resumes correctly after save;
- update `PROJECT_HANDOFF.md`, `CODE_WALKTHROUGH.md`, and README after the verified final head is known.
